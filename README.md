# 🐾 Go Pet Shop

**Go Pet Shop** — это учебный проект интернет-магазина товаров для питомцев, написанный на Go с использованием PostgreSQL.  
Он создан для отработки навыков работы с SQL-запросами, транзакциями и построения REST API.

---

## 🚀 Основная идея

Проект моделирует классический онлайн-магазин с товарами, пользователями, заказами и оплатами.  
Цель — показать полный цикл разработки от работы с базой данных и CRUD-операций до реализации транзакций и аналитики.

---

## 🔑 Возможности проекта

- 📦 Управление товарами (добавление, обновление, удаление, просмотр списка и конкретного товара).  
- 👤 Работа с пользователями (регистрация, получение списка и конкретного пользователя).  
- 🛒 Создание заказов и добавление позиций.  
- 💳 Оформление заказов в транзакции (уменьшение остатков, создание заказа, позиций и транзакции оплаты).  
- 📊 Просмотр истории заказов и аналитики (популярные товары, детали заказов и транзакций).  
- ✅ Health-check для проверки состояния сервера.

## 🛠 Как запустить

1. Клонировать репозиторий:
   `git clone https://github.com/pavloging/go-pet-shop.git`
   `cd go-pet-shop`

2. Настроить окружение: скопировать `.env.example` в `.env` и поправить логин, пароль и имя базы.
`cp .env.example .env`

3. Поднять PostgreSQL и применить миграции:
`docker compose up -d postgres`
`task migrate`

4. Запустить сервер (конфиг `config/local.yaml`, другой выбирается через `APP_ENV`):
`go run ./cmd/app`

5. После этого API будет доступно по адресу:
`http://localhost:8080`, проверка — `GET /health`.

Всё сразу в контейнерах: `docker compose up -d --build` (приложение берёт `config/dev.yaml`).

## 🧩 Версии проекта
В репозитории одна ветка `main`, это стартовая точка. Версии ты делаешь сам в своей копии проекта, каждую в отдельной ветке, по заданию модуля:

v1 — CRUD для товаров и пользователей.
v2 — Добавлены заказы и позиции заказа.
v3 — Оформление заказа в транзакции.
v4 — История заказов и аналитика (популярные товары).

## 🧪 Тесты
Тесты лежат в `internal/handlers/product/products_test.go` и проверяют четыре хендлера для товаров: получение списка, создание, обновление и удаление. Для каждого есть успешный случай и случай, когда хранилище вернуло ошибку. Для создания, обновления и удаления ещё проверяется плохой вход (кривой JSON или пустой id). Везде смотрим и код ответа, и тело. База данных для тестов не нужна, вместо неё подставляется мок.

### Чем отличаются ветки
Тесты здесь сделаны двумя способами, каждый в своей ветке. Сами проверки одинаковые, отличается только то, как создаётся мок хранилища.

- `tests-manual` — мок написан руками. Он лежит в `internal/handlers/product/product_mock.go`: структура `ProductsMock` с полем-функцией на каждый метод интерфейса `Products`. В тесте просто пишешь, что вернуть: `&ProductsMock{GetAllProductsFunc: func(...) {...}}`. Хорошо, чтобы понять, как вообще работает мок. Минус в том, что при изменении интерфейса мок надо дописывать самому.
- `tests-mockery` — ручной мок удалён, вместо него мок генерирует утилита mockery прямо из интерфейса `Products`. Готовый файл лежит в `internal/handlers/product/mocks/Products.go`. В тестах мок создаётся через `mocks.NewProducts(t)`, а поведение задаётся так: `m.On("GetAllProducts", mock.Anything).Return(...)`. Если интерфейс поменялся, достаточно заново сгенерировать мок.

### Как запустить тесты
Из корня проекта:

```
go test ./...
```

Чтобы видеть каждый тест отдельно:

```
go test ./... -v
```

Запустить один тест (или группу по имени):

```
go test ./internal/handlers/product/ -run TestCreateProduct -v
```

### Как перегенерировать моки
Только для ветки `tests-mockery`. Над интерфейсом `Products` в `internal/handlers/product/products.go` стоит директива:

```
//go:generate go run github.com/vektra/mockery/v2@v2.53.7 --name=Products
```

Чтобы пересоздать мок после изменения интерфейса, запусти из корня:

```
go generate ./...
```

Файл `mocks/Products.go` обновится. При первом запуске Go скачает mockery, поэтому нужен интернет.

Если у тебя совсем новый Go и генерация падает с ошибкой вроде `export data version 5 is greater than maximum supported version 4`, значит, mockery этой версии пока не умеет читать файлы нового компилятора. У меня это случилось на Go 1.27.2. Помогло запустить генерацию со старым тулчейном, только на время этой команды (PowerShell):

```
$env:GOTOOLCHAIN = "go1.26.0"
go generate ./...
Remove-Item Env:GOTOOLCHAIN
```
